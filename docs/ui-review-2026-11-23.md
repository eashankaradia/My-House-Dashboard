## 3. What looks wrong or confusing — prioritised

### P1 — `/money`: "Coming up" shows 1 bill instead of 4. Real bug.

`src/app/(app)/money/page.tsx:48-53` filters `x.days >= 0` on
`bills.due_date`. Verified against the DB (scoped to the household via
`household_members`): there are 6 `monthly` household bills, and 5 of them have
a `due_date` in the past, so they are silently dropped:

| Bill | due_date | days from today |
| --- | --- | --- |
| Mortgage | 2026-07-10 | −136 |
| Sky Broadband | 2026-07-13 | −133 |
| Eon Next | 2026-07-20 | −126 |
| Home Insurance | 2026-07-21 | −125 |
| Sofa | 2026-09-03 | −81 |
| Water Severn Trent | 2026-12-01 | **+8** |

Only Water Severn Trent survives, so the card renders a heading, a large gap
and one lonely row. For a recurring monthly bill the **day of the month** is
what matters — `due_date` here is the date the bill was set up, not its next
occurrence. Project each bill forward to its next occurrence before sorting and
slicing to 4.

**`/dashboard`'s "Next bill due" card shares this root cause.** It currently
reads "1 Dec 2026 · Water Severn Trent · £166", which is right only by luck —
the next actual payments are Water 1 Dec, Sofa 3 Dec, Mortgage 10 Dec, Sky
13 Dec. If every bill's stored `due_date` were in the past the card would show
nothing at all.

### P2 — `/purchases`: items with no price render "£0". Real bug.

`effectivePrice()` in `purchases-grid.tsx` falls back to `p.price`, and
`purchases.price` is `0.00` for **every row** in this database — real prices
live on `purchase_options`. Any item with zero options therefore displays £0,
and its room total sums to £0:

- **Dressing Room — 1 item, £0** (Blinds – Dressing Room, 0 options)
- **Master Bedroom — 2 items, £0** (Bedroom Drawers, Curtains – Master Bedroom; 0 options each)
- **Upstairs Bathroom — 1 item, £0** (Towel Radiator, 0 options)

"£0" reads as *this is free*, not *nobody has priced this yet*. Needs a
distinct empty state ("—" or "No price yet") at both row level and section-total
level. Confirmed visually by expanding Master Bedroom: both rows show "£0"
(`.ui-screens/.probe_room-expanded.png`).

### P3 — `/projects`: task titles are cut off at phone width.

Measured in the DOM at 375px: the title element is 183px wide while the text
needs 229px — 46px lost. "Check the mortgage payment date" truncates, and
critically **"Sort out life insurance - Eashan" and "Sort out life insurance -
Neelam" become indistinguishable**, which is exactly the information that
matters. The row crams star + title + project tag + assignee + delete into
343px. The tag and assignee should drop to a second line on phones.

(It does apply `truncate`, so there *is* an ellipsis — the problem is the
truncation itself, not a missing ellipsis.)

### P4 — `/projects`: date field shows `mm/dd/yyyy`.

US date order in an app that prices everything in £ and formats dates
elsewhere as "1 Dec 2026". Visible in the add-task row at both widths.

### P5 — `/dashboard`: two stat cards that say nothing.

- **"Ready to buy — £0 — 0 items".** The Ready-to-buy panel was deliberately
  removed from `/purchases` in the strip-back, but this card survived and
  permanently reads zero. It is dead weight in the top third of the first
  screen users see.
- **"Savings balance £36,104 — Target £0/mo".** No target is set, so the hint
  line is noise. Either hide it or say "No monthly target set".

### P6 — `/dashboard`: "Week ahead" is an empty decoration.

A full-width card containing seven date boxes (MON 23 … SUN 29) with no
content in any of them. On a phone the seven boxes squeeze to ~43px each. It
costs a whole card and tells the user nothing.

### P7 — `/projects`: the counters contradict each other.

The stat card says **"Active projects 2"** while the tab immediately beside it
says **"Projects (3)"** — no qualifier explains the difference. Likewise
"Open tasks 9" duplicates "Tasks (9)" directly underneath. On a phone this is
two full-width cards for two numbers that are already on screen. There is also
a conspicuous empty gap (~60px) between "Search tasks…" and the
All tasks / Mine toggle row, which leaves that toggle visually orphaned.

### P8 — `/purchases`: the Sort control looks broken.

The pill reads "Sort: Rating (high → low)", but sort is applied to the filtered
list *before* grouping, so it only orders items **within** each room section;
the sections themselves are always alphabetical. With 7 sections holding 1–6
items each, nothing on screen looks sorted by rating. Either relabel it
("Sort within rooms") or sort the sections too.

### P9 — minor, Filters sheet affordance.

"Hide items with no options" and "Essential only" render as plain outlined
buttons with no switch, checkbox or active styling in the off state, so there
is no way to tell they are stateful toggles rather than actions. The sheet's
"Room" dropdown is also redundant on a page whose primary grouping is by room.

### P10 — minor, `/money` reads as double-counting.

The Mortgage is both a £1,805/month bill (inside "Bills each month £2,194")
and a separate record ("Mortgage left £415,000") sitting next to it. Defensible,
but a reader may well think the mortgage has been counted twice.

### P11 — not UI: the harness writes screenshots to the repo root.

`scripts/verify-ui.mjs:62` builds the path as `${OUT}${route.replace(...)}`
with no separator, so files land in the **repo root** as
`.ui-screens_money.png` rather than inside `.ui-screens/`. `.gitignore:39`
only ignores `.ui-screens/`, so those files show up as untracked and are one
`git add -A` away from being committed. Fix: `${OUT}/${route.replace(...)}`.
(The files from this pass were moved into `.ui-screens/`; the tree is clean.)

## 4. Phone-width pass (375×812)
